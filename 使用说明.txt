# 医疗健康助手项目使用说明

这是一套医疗健康 RAG 知识库问答系统。

最重要的数据流：
网页 index.html -> 网页逻辑 app.js -> FastAPI main.py -> 各个 router
-> SQLite / Chroma / OpenAI -> 把答案返回网页。

建议阅读顺序：
main.py -> models.py -> schemas.py -> routers/ask.py -> vector_store.py -> static/app.js

## 1. 项目入口与数据基础

app/main.py
- 项目总入口。
- 创建 FastAPI 应用，启动时初始化数据库，注册全部接口，提供网页和 /health 健康检查。

app/database.py
- 数据库连接与初始化。
- 决定 SQLite 数据库位置，也会为旧数据库自动补充新字段，不删除旧数据。

app/models.py
- 数据表蓝图。
- 定义病症、药物、健康资料、对话消息、回答反馈、知识库状态、版本快照、RAG 评测题和评测记录。

app/schemas.py
- 接口输入与输出的数据格式、校验规则。
- 例如：问题不能为空、资料可信度只能使用规定等级、问答接口返回哪些字段。

app/source_metadata.py
- 资料来源和可信度的统一规则。
- 判断资料是否待核验、是否更新时间过久，以及页面应显示的中文等级。

app/knowledge_versions.py
- 知识库资料的版本存档与恢复逻辑。
- 重建或恢复前保存病症、药物、健康资料快照，方便回退。

app/vector_store.py
- RAG 的核心模块之一。
- 把资料整理成文本切块，调用 OpenAI Embedding 写入 Chroma。
- 用户提问时，从 Chroma 找出语义最相近的资料。

## 2. 后端接口模块

app/routers/ask.py
- 最核心的问答流程。
- 安全关键词拦截 -> 读取历史 -> Chroma 检索 -> 调 OpenAI 生成 -> 保存问答、引用和检索过程。
- 也负责流式 SSE 输出。

app/routers/conditions.py
- 病症资料的新增、查询、修改、删除接口。

app/routers/drugs.py
- 药物资料的新增、查询、修改、删除接口。

app/routers/documents.py
- 健康资料的新增、查询、修改、删除接口。
- 也负责上传 .md 和 .txt 文件，支持单文件上传和批量上传。
- 批量上传接口会逐个返回成功或失败原因，不会因为一个坏文件丢掉其他合法文件。

app/routers/knowledge.py
- 知识库管理接口。
- 包括：资料搜索、待核验资料、重建 Chroma、知识库状态、查看和恢复资料版本。

app/routers/conversations.py
- 历史对话列表、打开、删除和导出 Markdown。
- 每条新回答会保存引用资料、检索范围、处理路径等元数据，重新打开历史对话仍能看到。

app/routers/feedback.py
- "有帮助 / 没帮助"反馈、反馈统计和改进建议。

app/routers/evaluation.py
- RAG 评测系统。
- 用默认题和自定义题检查检索是否找对资料，支持历史对比、问题诊断和质量门禁。

app/routers/__init__.py
- 把 routers 文件夹标记为 Python 包，本身基本没有业务逻辑。

## 3. 前端页面

app/static/index.html
- 页面骨架。
- 聊天框、历史会话、资料管理、质量面板、弹窗、导出按钮的位置都在这里。

app/static/app.js
- 页面交互逻辑。
- 发送问题、接收流式回答、显示引用、查看原文、管理资料、批量上传、重建知识库、提交反馈、运行评测、导出对话都在这里。

app/static/styles.css
- 全部页面样式与响应式布局。
- 不负责业务功能。

## 4. 测试

tests/conftest.py
- 测试环境准备。
- 创建临时数据库和测试版 FastAPI，不会碰正式资料库。

tests/test_api.py
- 自动测试题。
- 覆盖 CRUD、RAG、流式输出、反馈、知识库版本、评测、历史对话、对话导出等功能。

pytest.ini
- Pytest 的小配置文件。

## 5. Docker 与运行

Dockerfile
- Docker 镜像说明书。
- 基于 Python 3.12，安装依赖，复制项目，最后用 Uvicorn 启动 FastAPI。

docker-compose.yml
- 正式运行配置。
- 服务固定端口是 8003，加载 .env，并把数据库和 Chroma 保存到 Docker Volume 里。

docker-compose.test.yml
- 测试专用 Docker 配置。
- 使用临时数据库和临时 Chroma，不影响正式数据。

批量导入资料
- 页面中打开“管理资料”，在“文件导入”处一次选择多个 `.md` 或 `.txt` 文件。
- 接口地址：`POST /documents/upload-batch`，表单字段名是 `files`。
- 最多 20 个文件，单个文件不超过 200KB，批量总大小不超过 2MB。
- 导入成功后知识库状态会变成“待重建”，点击“重建知识库”后才会更新 Chroma。

后台重建知识库
- 页面点击“重建知识库”后，默认使用异步接口，不会让页面一直等待。
- `POST /knowledge/rebuild/async`：创建重建任务，返回任务编号，状态码是 202。
- `GET /knowledge/rebuild/jobs/{job_id}`：查询指定任务，状态有 `pending`（等待）、`running`（执行中）、`completed`（完成）、`failed`（失败）。
- `GET /knowledge/rebuild/jobs/active`：查询当前是否有等待或执行中的任务，刷新页面后也能恢复显示。
- 同一时间只允许一个重建任务，重复点击会返回已有任务，前端会继续查看它。
- 原来的 `POST /knowledge/rebuild` 同步接口仍然保留，主要用于兼容旧调用和测试。
- 重建失败时会把错误摘要保存到任务记录，便于定位问题；不会把完整程序堆栈返回给页面。

scripts/docker-up.sh
- 常用启动脚本。
- 处理 WSL 代理、构建镜像、首次迁移旧数据、启动容器。
- 启动命令：bash scripts/docker-up.sh

scripts/docker-test.sh
- 在 Docker 内执行全部自动测试。
- 测试命令：bash scripts/docker-test.sh

scripts/docker-manage.sh
- Docker 管理快捷入口。
- 可用命令：
  bash scripts/docker-manage.sh start
  bash scripts/docker-manage.sh status
  bash scripts/docker-manage.sh logs
  bash scripts/docker-manage.sh stop
  bash scripts/docker-manage.sh rebuild
  bash scripts/docker-manage.sh test

## 6. 配置与资料

.env
- 真实环境变量，例如 OpenAI Key、模型名、代理地址。
- 绝不能提交 GitHub，也不能发给别人。

.env.example
- .env 的公开模板，不含真实密钥。

requirements.txt
- Python 依赖清单。
- 包含 FastAPI、SQLModel、LangChain、Chroma、OpenAI、Pytest 等。

.gitignore
- 告诉 Git 不提交 .env、虚拟环境、数据库、缓存等本机文件。

.dockerignore
- 告诉 Docker 构建镜像时不要复制无关文件。

.github/workflows/tests.yml
- GitHub Actions 配置。
- 推送代码到 GitHub 时，GitHub 会自动安装依赖并运行测试。

sample_documents/睡眠健康提示.md
- 示例健康资料，可用于练习上传和 RAG 检索。

## 7. 不用手动修改的内容

medical_health.db
- 本地 SQLite 数据库文件。
- Docker 正式运行时，持续使用的数据主要放在 Docker Volume 里。

chroma_db/
- 本地 Chroma 向量数据目录。

.venv/
- Python 虚拟环境。

__pycache__/ 和 .pyc
- Python 自动生成的缓存。

.pytest_cache/
- 测试缓存。

.git/
- Git 内部版本记录。

## 8. 目前最值得理解的六个文件

1. app/main.py：服务如何启动、接口如何注册。
2. app/models.py：数据库里到底保存什么。
3. app/routers/ask.py：用户提问后，RAG 如何完整运行。
4. app/vector_store.py：资料如何变成向量、如何被检索。
5. app/static/app.js：网页如何调用后端并显示结果。
6. docker-compose.yml：项目如何在 Docker 中稳定运行。

记忆方法：
- main.py 是总开关。
- models.py 是数据库表格设计。
- ask.py 是问答总流程。
- vector_store.py 是 RAG 检索引擎。
- app.js 是网页操作员。
- docker-compose.yml 是部署运行说明书。
